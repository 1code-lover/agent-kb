# 知识库上传目标显式选择修复说明

- 日期：2026-07-16
- 类型：既有批准需求的实现偏差修复
- 需求来源：`docs/20260706-multi-kb-frontend-refactor/` 下已审核的 PRD、FRD、RTM
- 问题来源：用户在 `/knowledge` 页面执行粮仓知识库导入人工验收时发现

## 1. 问题

页面原先把 `default` 作为初始知识库。用户没有主动确认目标库时，文件上传和网页导入仍可能写入默认库；知识库创建后也没有自动选中新库。该行为与“先选择知识库，再导入”的既有需求冲突。

## 2. 修复目标

1. 页面初始不选择任何知识库，`default` 也必须显式选择。
2. 只允许已登记且 `status=active` 的知识库成为目标。
3. 未选择目标时禁用文档查询、文件上传和网页导入。
4. 新建 active 知识库后自动选中；删除当前知识库后清空选择。
5. 上传区和网页导入区同时展示知识库名称、`kb_id` 与落盘目录。
6. API 调用缺少 `kb_id` 时在前端立即失败，不静默回退到 `default`。
7. 知识库列表保留创建、重命名和删除能力，并使用独立选择按钮避免嵌套交互控件。

## 3. 范围

涉及 React 知识库页面、知识库 API 封装、选择规则纯函数、统一响应体解包和样式。后端 KB CRUD、目录化存储和共享索引设计不变。

## 4. 验收标准

- 初始页面标题为“请选择知识库”，三个功能标签均不可用。
- 侧边栏展示后端返回的真实知识库列表。
- 选中 `grain-knowledge-base` 后，只展示该库文档。
- 文件上传和网页导入显示同一目标 `grain-knowledge-base`。
- 缺少目标时前端 API 不发起请求。
- 新增纯规则模块行、分支、函数覆盖率不低于 80%。
- 前端构建、后端 KB 定向回归、浏览器 smoke 和格式检查通过。
