# Refactor 故事模板

按下面结构写，删掉不需要的提示语，不要保留模板说明。

```md
# [Refactor 标题]

## 基本信息
- 类型：refactor
- 日期：[YYYY-MM-DD]
- 相关模块：[模块/服务/页面]
- 相关文件：[文件路径，可列多项]

## 重构背景
[为什么这次重构值得做。写清原有实现的问题、复杂度、维护成本或性能瓶颈。]

## 重构方案
[主要拆分、抽象、收敛或替换了什么，核心结构怎么变。]

## 为什么这样重构
[说明这次重构的取舍，例如风险、迭代速度、兼容性、回归成本。]

## 其他方案与为什么没选
[1-2 个即可；如果是推断的，标注“推断”。]

## 风险控制与兼容性
[如何避免行为回归、如何保证兼容、是否分阶段落地。]

## 验证与结果
[测试命令、手工验证、结果。若未测试，明确写未执行。]

## 面试表达版本
[用第一人称，4-6 句话，能直接说出口。]
```

写作要求：

- `重构背景` 要能说明为什么不是“单纯改代码风格”。
- `重构方案` 要落到真实模块和真实拆分动作。
- `风险控制与兼容性` 是这类故事的重点，不要省略。
