# ThinkRAG 知识库智能问答 V1 功能设计（FRD）

## 1. 文档目的
将产品需求拆解为可开发、可联调、可测试的功能模块，统一当前实现方向：主线是知识库智能问答，不是 Agent 工作台重构。

## 2. 功能模块总览
1. 模型与参数配置
2. 知识库导入
3. 知识库管理
4. 智能问答
5. 来源展示与历史记录
6. 错误处理与可观测性

## 3. 功能设计

### M1 模型与参数配置
- 目标：为问答提供稳定的模型配置入口。
- 现有相关入口：
  - `api/routers/settings.py`
  - `frontend` 中模型配置相关页面
- 关键能力：
  - 配置 `provider/base_url/api_key/model`
  - 读取当前配置
  - 缺失配置时返回明确错误

### M2 知识库导入
- 目标：把本地文件和网页资料转换成可检索知识库。
- 现有接口：
  - `POST /api/kb/file/import`
  - `POST /api/kb/web/import`
- 输入：
  - 文件集合或 URL 集合
  - `chunk_size`
  - `chunk_overlap`
- 输出：
  - 导入数量
  - 成功/失败信息

### M3 知识库管理
- 目标：让用户可以查看和清理知识库内容。
- 现有接口：
  - `GET /api/kb/list`
  - `DELETE /api/kb/docs`
- 关键能力：
  - 展示文档列表
  - 删除指定文档
  - 删除后列表更新

### M4 智能问答
- 目标：基于知识库进行检索增强问答。
- 现有接口：
  - `POST /api/chat/query`
- 关键能力：
  - 接收用户问题
  - 调用检索与生成链路
  - 返回回答
  - 保留会话维度上下文

### M5 来源展示与历史记录
- 目标：提升结果可信度和可追溯性。
- 现有接口：
  - `GET /api/chat/history`
  - `DELETE /api/chat/history`
- 关键能力：
  - 回答展示来源片段
  - 支持查看历史消息
  - 支持清理历史消息

### M6 错误处理与可观测性
- 目标：让用户能理解失败原因，便于排查和恢复。
- 关键能力：
  - 文件导入错误提示
  - 网页导入错误提示
  - 模型不可用提示
  - 问答失败提示

## 4. 页面级设计

### P1 Query 页面
- 对应：`frontend/Document_QA.py`
- 职责：
  - 输入问题
  - 发起问答
  - 展示回答
  - 展示来源

### P2 File 页面
- 对应：`frontend/KB_File.py`
- 职责：
  - 上传文件
  - 触发导入
  - 展示导入结果

### P3 Web 页面
- 对应：`frontend/KB_Web.py`
- 职责：
  - 输入 URL
  - 触发网页导入
  - 展示导入结果

### P4 Manage 页面
- 对应：`frontend/KB_Manage.py`
- 职责：
  - 展示知识库文档列表
  - 删除指定文档

## 5. 交互规则
1. 先导入资料，再发起问答。
2. 页面展示必须围绕“知识库问答”主流程命名。
3. 问答结果默认展示回答，并允许查看来源。
4. 错误提示优先说明原因，其次给出建议动作。

## 6. 异常处理
1. 导入文件失败：提示文件格式、读取或索引构建错误。
2. 导入网页失败：提示 URL 抓取或解析错误。
3. 问答失败：提示模型配置、索引状态或调用失败原因。
4. 历史读取失败：提示会话状态异常但不影响继续发起新问答。

- 统一问答返回结构
- 统一异常响应

### 前端
- Query / File / Web / Manage 页面体验梳理
- 来源信息展示优化
- 导入和问答反馈优化

### 测试
- 接口用例
- 主流程回归
- 异常路径校验

## 8. DoD
