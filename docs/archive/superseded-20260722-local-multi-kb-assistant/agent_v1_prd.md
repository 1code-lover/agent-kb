# ThinkRAG 知识库智能问答 V1 需求文档（PRD）

## 1. 文档信息
- 文档版本：v1.0
- 文档状态：评审稿
- 编码要求：UTF-8
- 适用范围：ThinkRAG 本地知识库智能问答产品

## 2. 项目背景
ThinkRAG 当前已经具备知识库导入、知识库管理和问答能力，真实代码主链路包括：

- 知识库导入与管理：`/api/kb/file/import`、`/api/kb/web/import`、`/api/kb/list`、`/api/kb/docs`
- 问答接口：`/api/chat/query`
- Streamlit 页面：`frontend/Document_QA.py`、`frontend/KB_File.py`、`frontend/KB_Web.py`、`frontend/KB_Manage.py`

本轮产品目标不是把主流程切成 Agent 工作台，而是把 ThinkRAG 收敛为“本地知识库智能问答”产品：导入资料、构建知识库、发起问题、获得带来源的回答，并保证体验稳定、结果可解释、配置可维护。

## 3. 目标与成功标准

### 3.1 业务目标
1. 让用户可以基于本地知识库稳定完成智能问答。
2. 让导入、管理、检索、回答四个关键环节形成清晰闭环。
3. 让答案具备来源支撑，减少“只给结论、不知道依据”的体验问题。

### 3.2 成功标准
1. 用户可在单次使用中完成“导入文档/网页 -> 查询 -> 获得回答 -> 查看来源”。
2. 问答结果包含回答内容和可追溯来源信息。
3. 常见错误场景有明确提示，不出现静默失败。
4. 核心接口和主流程测试稳定通过。

## 4. 目标用户与场景

### 4.1 目标用户
- 个人知识工作者：需要基于私有资料进行快速问答。
- 团队内部使用者：需要把项目文档、流程文档、网页资料整理进知识库后检索。

### 4.2 核心场景
1. 上传 PDF、DOCX、PPTX 等文件并写入知识库。
2. 导入网页内容并写入知识库。
3. 输入问题，系统基于知识库返回回答。
4. 查看回答引用的来源片段，判断回答是否可信。
5. 管理知识库中的文档，删除失效或错误内容。

## 5. 范围定义

### 5.1 In Scope（V1）
- 本地文件导入知识库
- 网页 URL 导入知识库
- 知识库文档列表与删除
- 知识库问答
- 问答来源展示
- 模型配置与基础参数配置
- 会话历史查询与清理

### 5.2 Out of Scope（V1 不做）
- 多智能体协同
- 代码执行/命令审批作为主流程
- 桌面端工作台重构
- 复杂自动化编排
- 企业级权限体系

## 6. 功能需求

### FR-01 知识库导入
- 支持本地文件上传导入。
- 支持网页 URL 导入。
- 导入过程允许配置 `chunk_size` 和 `chunk_overlap`。
- 导入失败时返回明确错误信息。

### FR-02 知识库管理
- 支持查询知识库当前文档列表。
- 支持删除指定文档。
- 删除结果可明确反馈成功或失败。

### FR-03 智能问答
- 支持基于知识库进行问答。
- 支持会话维度的历史消息保存与读取。
- 支持基础模型配置驱动的回答生成。

### FR-04 来源与证据
- 回答结果需要带来源信息。
- 至少能够展示来源文件名、片段内容和相关度信息。
- 用户可以据此判断回答是否可靠。

### FR-05 配置与可用性
- 支持模型配置、参数配置和当前配置读取。
- 缺失必要配置时返回清晰提示。
- 系统首次使用具备可理解的操作路径。

### FR-06 稳定性与错误反馈
- 错误场景不应导致页面卡死或接口无响应。
- 对上传失败、检索失败、模型不可用等情况给出明确提示。

## 7. 非功能需求

### NFR-01 易用性
- 用户可以在较少页面切换下完成核心流程。
- 页面与接口命名保持“知识库问答”语义一致。

### NFR-02 可维护性
- 接口职责清晰：`/api/kb/*` 负责知识库，`/api/chat/*` 负责问答。
- 文档、代码、测试的范围描述一致。

### NFR-03 性能
- 小规模本地知识库下，单次问答应保持可接受响应时间。
- 导入和问答失败不影响后续继续使用。

### NFR-04 可追溯性
- 问答结果应包含来源信息。
- 会话历史可按 `session_id` 查询和清理。

## 8. 验收口径
1. 文件导入、网页导入、文档列表、文档删除、问答接口全部可用。
2. 主问答场景能返回回答和来源。
3. 典型异常路径有明确提示。
4. 回归测试通过，主流程稳定。
