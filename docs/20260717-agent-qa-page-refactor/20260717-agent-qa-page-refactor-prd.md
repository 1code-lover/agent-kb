# 20260717-agent-qa-page-refactor-prd

## 1. 背景

当前 `/agent` 页面更像 Agent runtime 调试台：默认走 `/api/agent/run`，主视觉包含工具模式、审批、回执、证据等高级能力，但缺少“基础问答”和“按知识库范围问答”的直观入口。用户已经明确反馈该页“特别丑”，且不符合问答产品预期。

## 2. 问题定义

1. 首页 `/` 与 `/agent` 默认落到高级 Agent 控制台，普通用户难以理解。
2. 页面缺少显式知识库选择器，用户无法直观看到“当前回答基于哪个知识库”。
3. 基础问答与知识库问答的能力虽然后端已有，但前端没有整理成产品化界面。
4. 问答主区视觉层级混乱，空态、来源、错误提示与高级能力混在一起。

## 3. 目标

### 3.1 本期目标
- 将 `/agent` 改造成“问答优先”的工作台。
- 支持两类核心能力：
  - 基础问答：不限定某个知识库范围，走现有问答链路。
  - 知识库问答：用户显式选择一个 active 知识库后，在该范围内问答。
- 保留原有 Agent 高级模式，但将其降级为次级入口。
- 在回答后展示可读来源信息，帮助用户验证回答出处。

### 3.2 非目标
- 本期不新增新的后端问答协议。
- 本期不重做 `/knowledge` 页面。
- 本期不实现多选知识库联查，只支持“全部范围”或“单知识库范围”。
- 本期不重做审批弹窗交互，只保留原行为。

## 4. 用户故事

1. 作为普通用户，我打开首页后应该直接看到一个像聊天问答产品的界面，而不是工具台。
2. 作为知识库使用者，我应该能明确选择“当前问答基于哪个知识库”。
3. 作为高级用户，我仍然需要进入 Agent 模式去执行读文件、命令、审批等更复杂的链路。
4. 作为测试人员，我需要清楚知道当前页面分别如何验证基础问答、知识库问答与高级模式入口。

## 5. 验收标准

1. `/agent` 页面顶层出现三个明确入口：基础问答、知识库问答、Agent 高级模式。
2. 基础问答可直接提交问题并显示回答。
3. 知识库问答在未选择 active KB 时禁止发送；选择后可提交并显示来源。
4. 页面上明确展示当前问答范围（全部范围或指定 KB）。
5. Agent 高级模式仍可进入原运行时界面，且不丢失审批/回执/证据区。
6. 前端构建通过，新增测试通过，文档同步完成。
