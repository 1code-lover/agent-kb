# ThinkRAG 多知识库 + React 前端重构 需求追踪矩阵（RTM）

## 1. 说明
- 目的：确保需求、实现、测试和验收一一对应。
- 原则：每条核心需求至少对应 1 个实现入口和 1 组测试验证。

## 2. 需求追踪矩阵

| 需求ID | 需求描述 | 实现入口 | 测试类型 | 验收标准 |
|--------|----------|----------|----------|----------|
| FR-01 | 知识库目录管理（CRUD） | `api/routers/kb.py`、`api/services/kb_service.py`、`server/kb_registry.py` | 接口测试 | 可创建/查询/更新/删除知识库，kb_id 唯一不可改 |
| FR-02 | 多知识库导入 | `api/routers/kb.py`（POST file/import, web/import）、`api/services/kb_service.py` | 接口测试 | 导入时指定 kb_id，文档归属正确 |
| FR-03 | 多知识库查询 | `api/routers/chat.py`、`api/services/chat_service.py` | 接口测试、场景测试 | 支持单库/多库查询，结果带 kb_id/kb_name |
| FR-04 | 文档列表（按 KB 隔离+分页） | `api/routers/kb.py`（GET list）、前端 KnowledgePage | 接口测试 | 按 kb_id 过滤列表，支持 page/page_size/total_count |
| FR-05 | 文档删除（按 KB 隔离） | `api/routers/kb.py`（DELETE docs） | 接口测试 | 只能删除当前 KB 下的文档 |
| FR-06 | 文档预览 | `api/routers/kb.py`（GET preview）、前端 Preview 组件 | 接口测试、前端测试 | PDF 分页浏览，文本全文展示 |
| FR-07 | React 统一知识库页面 | `src/pages/KnowledgePage.jsx`、`src/components/ShellLayout.jsx` | 前端功能测试 | 左侧 KB 列表，右侧文档/上传/导入 Tab |
| FR-08 | 前端样式与导航修复 | `src/styles.css`、`src/components/ShellLayout.jsx` | 视觉检查、功能测试 | 97 个 CSS 类补全，所有页面导航可达 |
| FR-09 | Streamlit 废弃 | `README.md` 更新 | 文档检查 | React 为唯一入口 |
| NFR-01 | 易用性 | 前端所有页面 | 交互走查 | 上传 ≤3 步，操作反馈明确 |
| NFR-02 | 可维护性 | 后端接口设计 | 代码评审 | 接口职责清晰，遵循设计文档 |
| NFR-03 | 性能 | 全链路 | 性能测试 | 列表<500ms，查询<2s，上传≤100MB |
| NFR-04 | 稳定性 | 前后端 | 异常测试 | 所有错误场景有明确提示 |

## 5. 测试策略

### 5.1 覆盖率目标
- 后端接口：>= 80%
- 前端组件：>= 70%
- 整体覆盖率：>= 75%

### 5.2 回归测试策略
- 每个阶段完成后执行回归测试
- 核心功能（问答、导入）必须在每个阶段回归
- 回归范围：SC-01 至 SC-05（主流程）
- 新增接口必须配套单元测试

### 5.3 测试执行顺序
1. 单元测试（后端接口）
2. 接口测试（API 层）
3. 前端组件测试
4. 场景测试（端到端）
5. 回归测试

## 6. 发布门禁
1. FR-01 至 FR-09 覆盖率 100%
2. SC-01 至 SC-10 全部通过
3. 阻断问题为 0
4. 后端接口覆盖率 >= 80%
5. 所有文档使用中文 UTF-8 且命名符合规范
