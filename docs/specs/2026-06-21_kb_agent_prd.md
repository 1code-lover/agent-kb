# 知识库检索 Agent 需求文档（PRD）

## 1. 文档信息
- 文档版本：v2.0
- 文档状态：评审稿
- 适用范围：ThinkRAG 桌面版知识库问答系统

## 2. 项目背景

当前 ThinkRAG 已有知识库检索功能，但存在以下问题：
- 知识库只有一个，不支持多领域
- 用户无法选择特定知识库
- 检索流程简单，无 query 改写
- 缺少端到端的问答流程

## 3. 核心目标

**第一版核心功能**：基于知识库的问答系统

### 3.1 业务目标
1. 支持多领域知识库维护
2. 用户可显式选择知识库 or 系统自动路由
3. 实现完整的问答流程：提问 → 检索 → 排序 → LLM 生成答案

### 3.2 成功标准
1. 用户可创建和管理多个知识库
2. 用户可选择特定知识库进行问答
3. 系统可自动路由到相关知识库
4. 回答基于知识库内容，有据可查

## 4. 功能定义

### 4.1 功能模块

| 模块 | 功能 | 说明 |
|------|------|------|
| 知识库管理 | 文档上传、分块、向量化 | 支持多知识库 |
| 语义检索 | 根据问题找相关文档 | 向量检索 + BM25 |
| 答案生成 | 用 LLM 基于检索结果回答 | 构建提示词 → 调用 LLM |

### 4.2 核心流程

```
用户提问
    ↓
知识库选择（用户指定或自动路由）
    ↓
Query 改写（基于上下文）
    ↓
转换成向量（Embedding）
    ↓
在知识库中检索 Top-K 相关文档
    ↓
构建提示词（问题 + 文档上下文）
    ↓
调用 LLM
    ↓
返回答案（含来源引用）
```

## 5. 用户场景

### 场景1：用户指定知识库
```
用户：选择"技术文档"知识库 → 提问"如何配置环境" → 系统基于技术文档回答
```

### 场景2：系统自动路由
```
用户：不选择知识库 → 提问"公司考勤制度" → 系统自动路由到"HR制度"知识库回答
```

### 场景3：多知识库检索
```
用户：选择多个知识库 → 提问"技术方案" → 系统检索多个知识库并综合回答
```

### 场景4：多轮对话
```
用户：什么是流程管理？
系统：流程管理是...
用户：什么意思？（澄清追问）
系统：（结合上下文）流程管理的含义是...
```

## 6. 功能需求

### FR-01 多知识库管理
- 支持创建多个知识库（如：技术文档、HR制度、产品手册）
- 每个知识库独立维护文档
- 支持文档上传、分块、向量化
- 支持知识库的增删改查

### FR-02 知识库选择
- 用户可显式选择一个或多个知识库
- 用户可选择"自动路由"模式
- 系统根据问题内容自动匹配知识库

### FR-03 语义检索
- 支持向量检索（语义相似度）
- 支持 BM25 检索（关键词匹配）
- 支持混合检索（向量 + BM25 融合）
- 返回 Top-K 相关文档

### FR-04 Query 改写
- 检测澄清追问（"什么意思"、"详细说明"）
- 结合上一轮话题进行改写
- 保持原始问题语义
- 多轮对话上下文补全：当用户问题含指代词（如"它"、"这个"、"该方法"）时，结合对话历史补全为完整独立问题

### FR-05 多轮对话管理
- 基于 session_id 维护对话状态
- 支持对话历史的存储与读取（复用现有 `server/stores/chat_store.py`）
- 对话历史窗口管理：最近 3 轮完整保留，更早的对话压缩为摘要
- 支持上下文窗口大小可配置（适配不同 LLM 的 token 限制）

### FR-06 答案生成
- 构建提示词：问题 + 检索结果
- 调用 LLM 生成答案
- 标注证据来源（文件名、页码）
- 支持多轮对话上下文

## 7. 技术选型

### 7.1 Embedding 模型
- **模型**：BAAI/bge-large-zh-v1.5（中文优化）
- **维度**：1024
- **用途**：将文本转换为向量

### 7.2 LLM 模型
- **首选**：OpenAI 兼容 API（GPT-4/DeepSeek/Moonshot）
- **备选**：本地部署（Ollama + Llama/Qwen）
- **用途**：基于检索结果生成答案

### 7.3 向量数据库
- **开发模式**：LlamaIndex 内置 SimpleVectorStore（现有 `server/stores/docstore.py`）
- **生产模式**：Milvus（现有 `server/stores/vector_store.py`，已完整实现）
- **用途**：存储和检索向量

### 7.4 检索策略
- **向量检索**：语义相似度
- **BM25 检索**：关键词匹配
- **混合检索**：向量权重 0.6 + BM25 权重 0.4

## 8. 数据结构

### 8.1 知识库
```json
{
  "kb_id": "tech-docs",
  "name": "技术文档",
  "description": "技术相关文档",
  "created_at": "2026-06-21",
  "doc_count": 10,
  "chunk_count": 500
}
```

### 8.2 检索请求
```json
{
  "question": "如何配置环境",
  "session_id": "default",
  "kb_ids": ["tech-docs"],
  "context_mode": "auto",
  "max_results": 5
}
```

### 8.3 检索响应
```json
{
  "answer": "根据技术文档，配置环境需要...",
  "evidence": [
    {
      "kb_id": "tech-docs",
      "source": "环境配置指南.md",
      "page": "1",
      "score": 0.85,
      "excerpt": "配置步骤：1. 安装..."
    }
  ],
  "confidence": 0.9,
  "rewritten_query": "如何配置开发环境",
  "kb_used": ["tech-docs"]
}
```

## 9. 接口设计

### 9.1 知识库管理接口
- `POST /api/kb/create` - 创建知识库
- `GET /api/kb/list` - 列出所有知识库
- `PUT /api/kb/{kb_id}` - 更新知识库
- `DELETE /api/kb/{kb_id}` - 删除知识库
- `POST /api/kb/{kb_id}/import` - 导入文档

### 9.2 检索接口
- `POST /api/kb/search` - 知识库检索
  - 参数：question, kb_ids, session_id, context_mode
  - 返回：answer, evidence, confidence

## 10. 验收标准

### 10.1 功能验收
1. 用户可创建多个知识库
2. 用户可上传文档到知识库
3. 用户可选择特定知识库进行问答
4. 系统可自动路由到相关知识库
5. 检索流程包含 query 改写
6. 回答基于知识库内容，有来源引用
7. 支持多轮对话上下文

### 10.2 性能验收
1. 向量化延迟 ≤ 100ms/文档（不含模型首次加载）
2. 检索延迟 ≤ 200ms（不含 LLM）
3. 端到端响应时间 ≤ 3s（含 LLM，基于 GPT-4o 实测，实际延迟可能因模型而异）
4. 检索准确率（Top-5 命中率）≥ 80%

### 10.3 质量验收
1. 单元测试覆盖率 ≥ 80%
2. 集成测试通过
3. 无 P0/P1 级 bug

## 11. 范围定义

### 11.1 In Scope（V1）
- 多知识库管理
- 用户显式选择知识库
- 系统自动路由（关键词匹配）
- Query 改写（含多轮对话上下文补全）
- 语义检索（向量 + BM25）
- 基于 LLM 的答案生成
- 多轮对话管理（session 状态维护、对话历史窗口管理）

### 11.2 Out of Scope（V1）
- 复杂的意图识别
- 多 Agent 协同
- 知识图谱
- 多模态检索

## 12. 实现优先级

### P0（核心）

- 语义检索

- 置信度评估
