# Phase 2 需求文档（PRD）- 工具注册表和安全执行增强

## 1. 文档信息
- 文档版本：v1.0
- 文档状态：评审稿
- 适用范围：ThinkRAG Agent 工具注册表和安全执行模块
- 目标读者：产品、研发、测试

## 2. 项目背景

Phase 1 已完成 Agent 工作台 MVP，实现了基础的工具调用（kb_search、read_file、run_cmd）和审批流程。但当前实现存在以下问题：

1. **工具耦合度高**：工具逻辑直接写在 `agent_tools.py` 中，难以扩展
2. **风险分级粗糙**：仅有 low/medium/high 三级，无法满足复杂场景
3. **安全防护不足**：缺乏硬拒绝机制，高危命令可能被误批准
4. **命令解析简单**：不支持管道命令和复杂命令链
5. **回执存储临时**：回执仅存于内存，重启后丢失

## 3. 目标与成功标准

### 3.1 业务目标
1. 建立可扩展的工具注册表架构
2. 提供更细粒度的风险分级控制
3. 增强命令执行的安全防护
4. 支持复杂命令的解析和评估
5. 实现回执的持久化存储

### 3.2 成功标准
1. 新工具可通过注册表快速接入，无需修改核心代码
2. 风险分级覆盖 L0-L3 四级，映射规则清晰
3. 高危命令（如 rm -rf）被硬拒绝，不可绕过
4. 管道命令（`|`、`&&`、`;`）可正确解析和风险评估
5. 回执数据在服务重启后可恢复

## 4. 用户与场景

### 4.1 目标用户
- 开发者：需要扩展新工具能力
- 安全管理员：需要配置风险规则
- 终端用户：使用 Agent 执行任务

### 4.2 核心场景

#### 场景 1：工具扩展
用户需要添加一个新的 `git_commit` 工具，通过注册表注册即可使用，无需修改运行时代码。

#### 场景 2：精细风险控制
执行 `python --version` 为 L0（无风险），`pip install package` 为 L1（低风险），`rm temp.txt` 为 L2（中风险），`rm -rf /` 为 L3（高风险+硬拒绝）。

#### 场景 3：管道命令解析
用户输入 `cat file.txt | grep error | wc -l`，系统解析为三个子命令，分别评估风险，取最高风险等级。

#### 场景 4：回执追溯
用户重启应用后，仍可查看历史任务的执行回执和审批记录。

## 5. 范围定义

### 5.1 In Scope（Phase 2）
- 工具注册表框架（ToolRegistry）
- 工具 Schema 定义和验证
- L0-L3 四级风险分级
- 硬拒绝命令模式
- 命令管道解析
- 回执持久化存储（SQLite）
- 单元测试和集成测试

### 5.2 Out of Scope（Phase 2 不做）
- 工具热加载/卸载
- 分布式工具执行
- 自定义风险规则 UI 配置
- 回执数据迁移工具

## 6. 功能需求

### FR-01 工具注册表
- 提供统一的工具注册和发现机制
- 支持工具 Schema 定义（输入/输出）
- 支持工具自动调用和路由

### FR-02 工具 Schema 验证
- 工具输入必须符合定义的 Schema
- 工具输出必须符合定义的 Schema
- 验证失败时返回清晰的错误信息

### FR-03 L0-L3 风险分级
- L0：无风险（如查看类命令）
- L1：低风险（如只读操作）
- L2：中风险（如文件修改）
- L3：高风险（如系统级操作）

### FR-04 硬拒绝命令模式
- 定义不可执行的命令模式列表
- 硬拒绝命令无论是否审批都不执行
- 硬拒绝事件记录到审计日志

### FR-05 命令管道解析
- 支持 `|`、`&&`、`;` 等管道符号
- 对每个子命令独立风险评估
- 取最高风险等级作为整体风险

### FR-06 回执持久化
- 回执存储支持 SQLite 后端
- 支持按会话查询回执
- 支持按时间范围查询回执

## 7. 非功能需求

### NFR-01 可扩展性
- 新工具注册不超过 10 行代码
- 工具列表可动态扩展

### NFR-02 安全性
- 硬拒绝命令覆盖率 100%
- L2/L3 命令审批覆盖率 100%

### NFR-03 性能
- 工具调用延迟增加不超过 10ms
- 回执查询响应时间 < 100ms

### NFR-04 可维护性
- 模块边界清晰
- 单元测试覆盖率 >= 80%

## 8. 依赖与风险

### 8.1 关键依赖
- Phase 1 工具调用框架
- FastAPI 路由层
- SQLite 数据库

### 8.2 关键风险
- 现有工具迁移可能引入兼容性问题
- 命令解析可能遗漏边界情况
- SQLite 并发写入性能

## 9. 验收口径

1. 工具注册表可正常注册和调用工具
2. L0-L3 风险分级映射正确
3. 硬拒绝命令不可执行
4. 管道命令正确解析和评估
5. 回执数据持久化存储可用
6. 所有单元测试通过
7. 集成测试通过
