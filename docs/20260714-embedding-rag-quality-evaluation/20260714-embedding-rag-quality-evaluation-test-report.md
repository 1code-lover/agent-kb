# 嵌入检索与 RAG 问答质量测试报告

## 1. 基本信息

- 报告日期：2026-07-14
- 测试环境：Windows / PowerShell / 系统 Python 3.12
- API：`http://127.0.0.1:18080`
- Web：`http://127.0.0.1:5173`
- 嵌入模型：`BAAI/bge-small-zh-v1.5`
- 向量维度：512
- 当前检索配置：`top_k=5`、`use_reranker=false`
- 当前 LLM 状态：未配置、未启用

## 2. 最终结论

本轮判定为 **导入链路通过，嵌入基础召回部分通过，端到端问答待配置 LLM 后继续**。

1. **现在可以导入知识库**：不需要先配置阿里百炼。独立测试库已成功导入 1 个 UTF-8 中文文本文件，并生成 1 个索引分块。
2. **当前 BGE 小模型可用，但不能直接认定质量优秀**：20 组相近主题中文测试中，Recall@3 为 95%，Recall@5 为 100%，说明候选覆盖可用；Recall@1 只有 50%，MRR 为 0.71，且 10/20 的正确段落分数低于最高干扰项，首位排序能力偏弱。
3. **当前没有启用重排**：`use_reranker=false`。在候选召回较好、首位排序偏弱的情况下，重排模型或更大的嵌入模型值得做对照实验，但不能在没有对比数据时直接启用为默认方案。
4. **现在还不能完成最终问答质量验收**：问答接口需要 LLM。未配置 LLM 时返回 503 和明确错误，符合当前设计。

## 5. UTF-8 中文嵌入烟测结果

### 5.1 汇总指标

| 指标 | 结果 | 判定 |
|---|---:|---|
| 测试用例 | 20 | 小规模探索集 |
| Recall@1 | 50% | 偏低 |
| Recall@3 | 95% | 通过本轮烟测门槛 |
| Recall@5 | 100% | 与当前 `top_k=5` 配置匹配 |
| MRR | 0.71 | 有优化空间 |
| 平均 margin | 0.0109 | 区分度较弱 |
| 最小 margin | -0.1187 | 存在明显误排 |
| 负 margin | 10/20 | 首位排序不稳定 |
| 模型初始化 | 40.409 秒 | 冷启动较慢 |
| 20 个文档嵌入 | 0.326 秒 | 约 16.3 ms/文档 |
| 20 个查询嵌入 | 0.383 秒 | 约 19.2 ms/查询 |

### 5.2 典型表现

表现较好：

- 嵌入模型名称、重排作用、`top_k`、PDF 文字层、API/Web 端口、启动脚本等问题正确段落排第 1。

容易混淆：

- “未配置 LLM 是否可导入”与“生成答案何时需要 LLM”；
- “空知识库报错”与“无答案拒答”；
- “PDF 文字层提取”与“扫描 PDF OCR”；
- “API 18080”与“Web 5173/CORS”；
- “检索指标”与“重排模型作用”。

这说明模型对大方向语义有召回能力，但在同领域、短文本、相近概念之间的精细排序仍不足。

## 7. 风险与限制

1. 测试集仅 20 组、以项目领域合成文本为主，不能代表真实业务文档的生产质量。
2. 当前每份测试事实集中在一个分块中，尚未覆盖长文档分块边界、跨段答案和多文档竞争。
3. 当前没有评估 `bge-large-zh-v1.5`，也没有评估 `bge-reranker-base` 对排序的提升。
4. 当前 LLM 未配置，答案正确性、忠实度、引用和拒答尚未执行。
5. 测试知识库和文件保留在本地运行数据中，目录受 `.gitignore` 管理，不会进入 Git。

## 8. 推荐下一步

1. 保留当前嵌入与导入结果作为基线。
2. 在模型配置页填写阿里百炼 API Key，选择 `qwen-plus` 或 `qwen-flash`，先执行“测试当前模型”，成功后再保存并启用。
3. 使用固定 QA 集执行端到端问答，分别记录检索指标和生成指标。
4. 对首位排序问题做两组对照：启用 `bge-reranker-base`；改用 `bge-large-zh-v1.5`。比较 Recall@1、MRR、耗时与内存后再决定默认配置。
5. 扩展到真实业务样本时，增加长文档、多文档、无答案、多知识库隔离和引用准确性用例。
