# 嵌入检索与 RAG 问答质量测试方案

## 1. 基本信息

- 日期：2026-07-14
- 专题：嵌入检索与 RAG 问答质量评估
- 当前阶段：本地嵌入与导入探索性烟测；阿里百炼尚未配置
- 测试对象：`bge-small-zh-v1.5`、文件导入链路、知识库隔离、问答前置条件

## 2. 测试目标

1. 确认未配置云端 LLM 时，本地知识库文件仍可导入并建立向量索引。
2. 用 UTF-8 中文语义匹配集评估当前嵌入模型的基础召回质量。
3. 将嵌入检索质量与 LLM 生成质量分开检测，避免用最终答案反推检索问题。
4. 明确配置阿里百炼后的端到端问答测试口径。

## 3. 测试顺序

```text
本地嵌入模型初始化
→ UTF-8 中文语义检索评估
→ 独立测试知识库真实导入
→ 知识库范围检索验证
→ 配置并测试阿里百炼连接
→ 固定 QA 集端到端问答评估
```

说明：文件导入仅依赖嵌入模型；最终答案生成才依赖 LLM。因此不应先配置阿里百炼再判断嵌入是否可用。

## 4. 数据集设计

### 4.1 嵌入语义烟测集

- 规模：20 组中文查询与目标段落。
- 领域：知识库导入、LLM 前置条件、BGE、重排、PDF/OCR、端口、CORS、多知识库隔离、质量指标。
- 难度：包含相近主题的干扰段落，例如“空知识库”和“无答案拒答”、“文字层 PDF”和“扫描 PDF OCR”、“API 端口”和“Web 端口”。
- 编码：由 UTF-8 文件直接读取；执行前后检查中文未转换成问号。

### 4.2 真实导入样本

- 独立知识库：`embedding-quality-smoke-20260714`
- 文档：`northagent_embedding_smoke.txt`
- 内容：5 条不含隐私的合成事实。
- 分块参数：`chunk_size=256`、`chunk_overlap=32`。

## 5. 指标

| 指标 | 含义 | 关注点 |
|---|---|---|
| Recall@1 | 正确段落排第一的比例 | 直接反映首条命中能力 |
| Recall@3 | 正确段落进入前三的比例 | 适合评估小范围候选召回 |
| Recall@5 | 正确段落进入前五的比例 | 对应当前 `top_k=5` 的候选覆盖 |
| MRR | 正确段落排名倒数的平均值 | 同时反映是否命中及排名位置 |
| 相似度 margin | 正确段落分数减最高干扰段落分数 | 小于 0 表示干扰项排在正确项之前 |
| 嵌入耗时 | 模型初始化、文档批量嵌入、单查询嵌入 | 识别冷启动与在线性能风险 |
| 导入结果 | HTTP 状态、`indexed_chunks`、文档列表、`kb_id` | 验证真实持久化链路 |

## 6. 判定规则

### 6.1 本轮探索性烟测

- 模型可初始化并输出固定维度向量。
- Recall@3 不低于 90%。
- 真实文件导入返回 200 且 `indexed_chunks > 0`。
- 按测试知识库过滤后能检索到目标节点。
- 未配置 LLM 时问答接口应明确返回模型未配置错误，而不是误报知识库导入失败。

### 6.2 建议的正式发布门槛

正式门槛需要在扩大到真实业务 QA 集后评审确认。建议至少关注：Recall@1、Recall@3、MRR、负 margin 比例、无答案拒答、引用正确性、多知识库隔离和答案忠实度。不能仅用一个综合分数判定。

## 7. 端到端问答测试设计

配置阿里百炼并通过连接测试后，复用固定 QA 集，分别记录：

1. 检索：Recall@K、MRR、命中片段和 `kb_id`。
2. 答案正确性：关键事实是否正确。
3. 忠实度：答案是否只使用检索上下文中的事实。
4. 引用：文件名、页码、知识库 ID 是否正确。
5. 无答案：知识库无依据时是否明确拒答。
6. 隔离：只选择一个知识库时是否出现其他库内容。
7. 稳定性：同一问题重复 3 次时结论是否一致。

## 8. 安全与数据要求

- 不在脚本、日志、截图或报告中记录阿里云 API Key。
- 云端连接测试只提交必要的最小测试提示词。
- 真实业务文档进入云端问答前先确认数据合规；本轮仅使用合成文本。
