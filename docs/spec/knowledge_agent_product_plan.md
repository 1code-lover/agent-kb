# ThinkRAG 知识库智能问答产品规划

## 1. 产品定位
ThinkRAG 的主产品定位是“本地知识库智能问答系统”，不是通用 Agent 工作台。

产品核心价值：
- 用户可以把本地文件和网页资料整理进知识库。
- 用户可以基于知识库发起智能问答。
- 回答附带来源，便于验证结果可信度。
- 数据和知识库索引优先保存在本地。

## 2. 当前代码主线
当前仓库里已经形成了比较清晰的主能力边界：

- 问答接口：`/api/chat/query`
- 历史接口：`/api/chat/history`
- 知识库接口：`/api/kb/file/import`、`/api/kb/web/import`、`/api/kb/list`、`/api/kb/docs`
- 页面入口：`frontend/Document_QA.py`、`frontend/KB_File.py`、`frontend/KB_Web.py`、`frontend/KB_Manage.py`

因此后续规划应以“知识库问答闭环”为核心，而不是把主线改写成桌面 Agent 改造项目。

## 3. 产品目标

### 近期目标
1. 稳定知识库导入和管理。
2. 稳定问答结果与来源展示。
3. 统一产品文档、页面术语和接口语义。

### 中期目标
1. 提高检索效果和回答质量。
2. 优化来源展示与历史追踪。
3. 支持多知识库或多行业隔离。

### 远期目标
1. 在知识库问答主线稳定后，再评估更复杂的智能体能力。
2. 将智能体能力作为增强路径，而不是替代当前主产品。

## 4. 产品能力分层

### L1 基础能力
- 模型配置
- 文件导入
- 网页导入
- 文档管理

### L2 核心能力
- 检索增强问答
- 回答来源展示
- 历史消息查询与清理

### L3 增强能力
- 多知识库隔离
- 行业知识库隔离
- 检索策略和提示词优化

## 5. 后续规划原则
1. 先把知识库问答做好，再决定是否引入更复杂 Agent 能力。
2. 文档和实现必须与真实代码主链路一致。
3. 任何扩展方案都不能弱化“知识库智能问答”这个主叙事。
