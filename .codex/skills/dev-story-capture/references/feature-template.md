# Feature 故事模板

按下面结构写，删掉不需要的提示语，不要保留模板说明。

```md
# [Feature 标题]

## 基本信息
- 类型：feature
- 日期：[YYYY-MM-DD]
- 相关模块：[模块/服务/页面]
- 相关文件：[文件路径，可列多项]

## 需求背景
[为什么要做这件事，解决谁的什么问题。]

## 设计与实现方案
[方案核心结构、关键模块、主要实现路径。]

## 为什么选这个方案
[重点写约束、成本、迭代速度和可维护性。]

## 其他方案与为什么没选
[1-3 个即可；如果是推断的，标注“推断”。]

## 风险与权衡
[复杂度、兼容性、性能、维护成本、潜在副作用和控制方式。]

## 验证与结果
[测试命令、手工验证、结果。若未测试，明确写未执行。]

## 面试表达版本
[用第一人称，4-6 句话，能直接说出口。]
```

写作要求：

- `需求背景` 不要写成泛泛的“提升用户体验”。
- `设计与实现方案` 要落到真实模块和真实改动。
- `为什么选这个方案` 是这类故事最有价值的部分，优先写约束、成本、迭代速度和可维护性。
- `风险与权衡` 不要和 `为什么选这个方案` 重复，优先写潜在副作用和控制方式。
