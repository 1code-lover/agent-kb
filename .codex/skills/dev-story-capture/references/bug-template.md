# Bug 故事模板

按下面结构写，删掉不需要的提示语，不要保留模板说明。

```md
# [Bug 标题]

## 基本信息
- 类型：bug
- 日期：[YYYY-MM-DD]
- 相关模块：[模块/服务/页面]
- 相关文件：[文件路径，可列多项]

## 问题现象
[用户看到的错误、回归或异常表现。]

## 根因分析
[真正导致问题的原因。优先写代码层、状态层、数据层或流程层原因。]

## 解决方案
[改了什么，为什么这样改。]

## 为什么选这个方案
[说明方案选择依据，优先写约束、风险和成本。]

## 其他方案与为什么没选
[1-2 个即可；如果是推断的，标注“推断”。]

## 验证与结果
[测试命令、手工验证、结果。若未测试，明确写未执行。]

## 面试表达版本
[用第一人称，4-6 句话，能直接说出口。]
```

写作要求：

- `根因分析` 要能区分现象和原因。
- `解决方案` 不要只是重复 diff，要总结设计动作。
- `为什么选这个方案` 优先写约束、风险和成本，而不是空泛结论。
- `面试表达版本` 要像候选人在复盘自己的工作，不要像文档说明书。
