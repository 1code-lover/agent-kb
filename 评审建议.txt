本轮测试方案评审建议（2026-08-18）

一、优点
1. 文档目录和命名符合仓库规范，按迁移、OCR、Open API、Embedding 四个域建立了需求到测试的明确映射，并列出了专项、覆盖率、全量和 slow/runtime 命令。
2. 对 OCR 资产来源保持诚实：明确 captured 当前是项目排版截图、不是打印扫描/手机实拍，并把该项定义为外部资产待补，避免误报完成。
3. 测试方案覆盖真实 LlamaIndex 0.11.19 重载、物理索引隔离、结构化 search 与 answer 分离、审计脱敏、ModelScope metadata 超时回退、下载取消和预热门禁等高风险路径。
4. 验收门禁明确要求单模块 coverage >= 80%、修复后重新跑专项和全量、测试报告评审前不得 commit/push，符合仓库流程。

二、需要改进的地方
1. 迁移 RTM 仍缺“成功回滚”和“备份复制/写入权限失败”的直接服务层证据；当前只有篡改与所有权拒绝测试，不能完整证明 FR-MIG-03/08。
2. 令牌管理路由缺 create/list/revoke 正常链路和撤销后立即拒绝 Open API 的集成证据；CLI 生命周期不能替代管理 API 路由验收。
3. `llama_index.core.__version__` 在部分 0.11.x 环境未必公开，前置检查命令应改用 `importlib.metadata.version('llama-index-core')`，避免测试方案本身不可执行。
4. 覆盖率命令未覆盖新增 routers、`open_api_audit.py` 的文件写入分支、`build_ocr_scan_benchmark.py` 和 `manage_access_tokens.py`；若完成定义采用“新增/修改 Python 模块”，应扩展 coverage 范围或在报告中逐一解释非核心 CLI/路由模块的覆盖口径。
5. OCR runtime 报告虽然已生成，但测试方案应明确把真实运行 artifact 的当前实测值作为证据，并区分“算法/runtime 已通过”与“物理 captured 资产未满足”，避免最终判定含混。

三、具体建议
1. 增加迁移服务测试：成功迁移后执行 rollback，断言本批次目标被移动到 rollback 隔离目录、历史源和备份仍可用；注入 copy/write 权限异常，断言状态失败且无目标半成品。
2. 增加 access token route 集成测试：本机+正确 admin key 创建、列表不含明文、撤销；随后用该 token 请求 `/api/open/v1/me` 或 answer，断言立即 401。
3. 修订前置版本检查为 `importlib.metadata.version`。
4. 扩展覆盖率命令到新增 routers 和 CLI/基准模块；如某模块因薄路由/CLI 入口不适合 80% 单模块门禁，必须在测试报告中明确分类并给出直接行为测试证据，不能静默遗漏。
5. 在测试报告模板和 RTM 证据中记录已生成的 recorded/runtime JSON、Markdown 路径及 runtime 五项指标；最终状态应为“代码验收通过但 FR-OCR-01 外部实拍资产待补”，直到真实资产加入。
