需要改进：
1. mixed batch 正向用例虽然首要/目标文档、preview 与关键词均命中，但接口仍会返回多个候选 sources；`source_count_match/evidence_count_match` 精确数量检查为 false。若产品希望减少引用噪声，需要继续调 top-k、rerank 或前端证据展示策略。
2. `.claude/settings.local.json` 是本地权限配置变更，和项目功能代码无直接关系；提交前应确认是否排除，避免把个人工具权限配置混入功能提交。
3. 当前分支本地领先远端 4 个提交，且还有未提交工作区变更；继续开发前建议先按功能边界拆分提交并推送，降低后续 review 难度。
4. 多知识库目前仍是共享索引加 metadata 逻辑隔离，粮仓 QA 样本为 30 条，指标全绿但不能替代更大规模真实资料验收。

具体建议：
1. 提交前优先拆成三类改动：运行环境与项目进度文档、导入/检索/评测代码修复、QA 报告 artifact；`.claude/settings.local.json` 单独决定是否保留。
2. 下一轮修复建议优先收口正向问答 sources 偏多的问题：先明确产品是否允许多证据返回，再决定是调检索 top-k、rerank 阈值，还是只在前端突出首要证据。
3. 粮仓 QA 评测建议继续扩充 verified 用例，覆盖更多负向问题、跨库隔离问题、表格/扫描件来源问题，并在报告中持续保留 `cases_sha256`。
4. 在 commit 前再次执行 `/opt/miniconda3/envs/agent-kb/bin/python -m pytest -q`、前端 Node 单测、`npm run build`、`npm audit --json` 和 `git diff --check`，确认文档更新后仍无格式问题。
