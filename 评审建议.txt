最新评审建议（2026-08-10）

优点：
1. 模型配置韧性已覆盖额度耗尽、403、401、模型不可用和网络异常等可恢复错误，并在 chat query 中实现 fallback 后单次重试。
2. API 已增加 `GET /api/model/health`，`/api/model/options` 也返回 `model_health`，前端模型页和 Agent 页统一展示模型健康状态。
3. `scripts.run_grain_qa_eval` 已支持 `--resume` 和 `--stop-on-api-error`，长评测遇到模型失败时可以保留已成功用例。
4. 新增 `scripts.diag_desktop_model_workflow`，能验证模型 options/health、模型选择与探活、文件导入、问答、引用来源、preview 和跨 KB 隔离。
5. macOS 桌面启动问题已定位为旧 `electron@31.7.7` 公证撤销，升级到 `electron@43.3.0` 后桌面端可独立使用 conda `agent-kb` 环境启动 API。
6. 相关后端、前端和桌面启动测试均有覆盖，桌面 E2E 报告 `run_passed=true`。

需要改进的地方：
1. 当前 fallback 候选只覆盖 OpenAI-compatible 且具备 API Key 的模型，暂未支持 Ollama 自动候选探活。
2. fallback 依赖真实供应商探活，外部网络抖动时仍可能影响首次失败后的恢复速度。
3. Electron dev 模式仍有 CSP 安全提示，正式打包前需要补前端 CSP 策略。
4. `desktop` 依赖树仍有 npm audit 风险：`8 vulnerabilities`，需要后续单独安排构建依赖安全升级。

具体建议：
1. 本轮改动可以在完整回归通过后提交并推送，作为“模型韧性 + 桌面 E2E”阶段节点。
2. 下一轮建议做全知识库/多领域测试优化，复用桌面工作流诊断思路覆盖不同资料类型和跨领域 KB。
3. fallback 后的 UI 可继续增强为时间线通知，让用户明确知道“从哪个模型切到了哪个模型”。
4. 桌面端后续发布前应补打包签名、公证和 CSP 检查，避免开发态 Electron 问题进入正式分发链路。
